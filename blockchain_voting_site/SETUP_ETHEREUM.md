# Ethereum/Ganache setup for BlockVote

This version uses the existing Flask + SQLite application for login/election metadata and uses a real Solidity smart contract on a local Ethereum-compatible Ganache chain for election state, candidate registration, vote transactions, and result counts.

## 1. Install Python dependencies

```bash
pip install -r requirements.txt
```

## 2. Start Ganache

Open Ganache GUI and create/start a workspace.

Use the RPC URL shown by Ganache. The default is usually:

```text
http://127.0.0.1:7545
```

Copy the private key of the first Ganache account. **This is only a local demo account. Never use a real wallet private key.**

## 3. Compile and deploy the contract

Use Remix IDE for the easiest deployment:

1. Open `contracts/VotingSystem.sol` in Remix.
2. Select Solidity compiler `0.8.19` or newer compatible with the pragma.
3. Compile it.
4. In **Deploy & Run Transactions**, select **External HTTP Provider** and enter the Ganache RPC URL, or connect Remix to the Ganache network as available in your setup.
5. Deploy `VotingSystem` with the Ganache account whose private key you copied.
6. Copy the deployed contract address.

The project already contains `contracts/VotingSystem_abi.json` for the Flask/Web3 connection.
If you make changes to the Solidity contract, replace this ABI with the ABI generated by Remix.

## 4. Create `.env`

Copy `.env.example` to `.env` and fill in:

```text
GANACHE_RPC_URL=http://127.0.0.1:7545
GANACHE_PRIVATE_KEY=your_ganache_account_private_key
CONTRACT_ADDRESS=your_deployed_contract_address
```

The private key must belong to the **same Ganache account that deployed the contract**, because that account becomes the Solidity `admin`.

## 5. Run the Flask app

```bash
python app.py
```

Open:

```text
http://127.0.0.1:5000
```

## 6. Demo flow

1. Admin logs in.
2. Create an election.
   - Flask stores the election metadata in SQLite.
   - Flask also calls `createElection()` on the Solidity contract.
3. Add at least two candidates.
   - Candidate details are kept in SQLite while the election is being prepared.
4. Start the election.
   - Flask sends every candidate to `addCandidate()` on-chain.
   - Flask calls `startElection()`.
5. Voter logs in and selects a candidate.
6. Flask authenticates the voter and sends `vote(voterHash, candidateId)` through Web3.py.
7. Ganache mines the transaction.
8. The transaction hash is saved in SQLite for traceability.
9. Results are read from the Solidity contract's `getResults()` function.
10. The Blockchain page shows the contract address and vote transaction hashes.

## What to tell the teacher

> SQLite is used for application-level data such as voter accounts, authentication, election metadata and candidate details. The actual vote is submitted as a transaction to our Solidity smart contract deployed on Ganache. The smart contract maintains the election state and vote counts, and every vote has an on-chain transaction hash. Therefore the database is not being used as the blockchain; each component has a separate role.

## Important limitation to explain honestly

This is a local Ethereum-compatible development network, not Ethereum mainnet. Ganache gives the project an actual smart-contract/blockchain execution environment for the practical demonstration. The Flask server still authenticates voters, so this is not a production-grade decentralized election system.
